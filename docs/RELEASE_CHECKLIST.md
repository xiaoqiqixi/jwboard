# 商业发布检查清单

本清单用于 Nova 主题上线前的人工核验。全部通过后再开放注册、真实支付和节点。

## 安装与依赖

- [ ] 使用原版组合：Nginx 1.17、MySQL 5.6、PHP 7.4、Redis、Supervisor。
- [ ] 使用 `PHP_BIN=/www/server/php/74/bin/php bash init.sh` 完成安装；`vendor/autoload.php` 已生成。
- [ ] 首次成功安装生成的 `composer.lock` 已保存到你的私有代码仓库，后续只运行 `composer install`。
- [ ] `.env` 为生产值：`APP_ENV=production`、`APP_DEBUG=false`、强 `APP_KEY`。
- [ ] 数据库、Redis 仅绑定内网或 localhost；不使用 root 数据库账号。

## 安全

- [ ] 全站 HTTPS，`APP_URL` 与实际的 HTTPS 域名严格一致。
- [ ] `.env`、`storage`、`vendor` 未被 Web 访问；站点根目录是 `public`。
- [ ] `TURNSTILE_ENABLED=true`，已使用真实域名、真实浏览器验证注册和找回密码。
- [ ] 如启用 Telegram 一键登录，BotFather 的 `/setdomain` 已设置为当前 HTTPS 域名，且已完成普通注册、邀请码注册、登录与封禁账户拒绝的实际测试。
- [ ] `JWT_EXPIRE_SECONDS` 已设置合理值（默认 86400 秒）；通过等待过期或缩短测试值确认旧 token 被拒绝。
- [ ] 不记录订阅 URL、Authorization、支付密钥、Turnstile Secret 或节点密钥到 Nginx、应用或监控日志。
- [ ] 设置管理员强密码、独立后台路径，管理员账户启用最小权限。
- [ ] 禁用未使用 PHP 函数；本项目仅需要保留 `putenv`、`proc_open`、`pcntl_alarm`、`pcntl_signal`。

## 节点与支付（开放真实业务前必须完成）

- [ ] `SERVER_TOKEN` 为随机高强度值，且仅保存在面板 `.env` 与受控节点的 V2bX 配置中；泄露后必须同时更新面板和全部节点。
- [ ] 使用普通测试用户调用节点列表与订阅接口，确认响应中没有 Reality `privateKey`、`dest` 或 `serverPort`。
- [ ] 用测试用户验证节点用户同步、流量上报、到期停用、订阅重置与故障恢复。
- [ ] 每个支付网关使用测试模式完成：创建订单、回调、重复回调、支付失败、取消订单与退款人工流程。
- [ ] 订单金额、币种、商户订单号、回调签名均由服务端校验；不要相信前端返回的金额或支付状态。
- [ ] 对支付后台、数据库与 Redis 做每日备份；至少演练一次恢复。

## 运营与合规

- [ ] 上线前提供真实的服务条款、隐私政策、退款政策和联系渠道。
- [ ] 核实营业主体、支付服务商、服务器地区及目标客户所在地的适用法律、税务、数据保护与网络服务要求。
- [ ] 建立滥用投诉、账单争议、账号封禁、数据删除与安全事件响应流程。
- [ ] 设置错误率、队列积压、支付回调失败、节点离线和磁盘空间告警。

## 发布后

- [ ] 先向小范围测试用户开放 24–72 小时，确认支付、邮件、订阅和节点数据一致。
- [ ] 每次发布先备份数据库和 `.env`，再在预发布环境验证；生产环境只部署审查过的版本。
